# Mac os qq聊天bot

一个在 macOS 上运行的 QQ 聊天机器人：通过 QQ 的辅助功能界面读取消息、复制图片、输入回复并确认发送。原生 SwiftUI 菜单栏界面配合 Python 后台，适合自己配置 AI 接口后在本机使用。

**所有 AI 任务使用你配置的同一个原生多模态模型。** 没有内置供应商、GPT 分流、Codex 登录依赖、预设角色或已有聊天资料。聊天判断与回复、群聊风格总结、记忆压缩、网页与视频分析、主动话题、图片审核和 QQ 空间评论都走同一个 OpenAI 兼容接口。图片生成使用单独配置的生图接口。

这是独立开源版；应用标识、权限和本地偏好与私人版本分开。

## 功能

- 主群优先监听，按模型判断自然接话；可选扩展到 QQ 会话列表中的其他群和私聊。
- 会话历史和记忆按聊天隔离。收集文字消息后可总结本机的说话风格，并压缩较长摘要；支持反馈和自定义设定。
- 读取新图片并交给原生多模态模型，复制失败时不猜图。消息发送后回读 QQ 确认；发送结果不确定时暂停，避免重复发送。
- 菜单栏、实时状态窗口、请求用量与日志、设置热应用。
- 可选网页阅读、视频字幕与必要画面分析；可选主动话题与人工选择话题预览。
- 可选图片生成：有人明确 @ 并请求生成后审核、生成、发送；支持按每人滚动 24 小时计算的配额。
- 可选 QQ 空间浏览、看图、点赞和评论，跳过视频、不可读内容与已处理动态。
- 可选像素桌宠；默认关闭。

## 环境要求

- macOS 14 或更新版本，官方 Mac QQ 已安装并登录。
- Python 3.10 或更新版本。基础聊天功能只用 Python 标准库，无需安装 AI SDK。
- 一个 **OpenAI Chat Completions 兼容接口**，模型必须原生支持文字和图片（`image_url`）、中文与 JSON 输出。纯文字模型或独立 OCR 服务无法完整使用识图、视频和空间图片功能。
- 编译源码需要 Xcode Command Line Tools 或完整 Xcode。发布的现成应用包无需重新编译。
- 发布包为 Apple Silicon（arm64）；Intel Mac 请从源码在本机编译。

供应商名称用于自定义显示；实际请求发送到你填写的 URL。服务需返回标准 `choices[0].message.content`。地址可填 `https://你的服务/v1` 或完整的 `/chat/completions` 地址。仅提供其他原生协议的接口需要使用兼容端点或自行适配。

## 下载安装

到仓库的 **Releases** 下载：

- `Mac-os-qq-bot-macOS-arm64.zip`：现成应用和必需的 Python 源码、提示词及公开配置模板。
- `Mac-os-qq-bot-source.zip`：源码包，适合自行编译或修改。

解压后请保留整个文件夹。`QQChatBridge.app` 需要同目录的 Python 文件、`prompts/` 和 `config.example.json`；不能只把 `.app` 单独拖到其他目录。建议把整个文件夹放在你能读写的固定位置，再启动应用。

安装 Python 的一种方式是使用 Homebrew：

```sh
brew install python
```

如果 macOS 阻止打开未公证的应用，请在确认下载来自本仓库后，按系统提示使用“系统设置 → 隐私与安全性 → 仍要打开”。发布包使用临时签名，没有 Apple 开发者证书与公证。不要关闭整个系统的安全保护。

## 首次使用

1. 打开 QQ，登录准备使用的账号，保持 QQ 主窗口打开。
2. 启动 `QQChatBridge.app`。首次会从 `config.example.json` 创建仅本机使用的 `config.json`，自动显示设置。
3. 在“常规”填写 **本账号在 QQ 中显示的昵称**、**主群完整名称**。不是群友的昵称。主群名称须与 QQ 会话列表一致。需要 QQ 空间时另填本账号 QQ 号。
4. 在“AI 供应商”填写供应商名称、接口地址、API Key、模型名称与可选回复后缀。思考强度可留空，按供应商能力选择；请求超时和超时重试可调整。
5. 点击“打开权限设置”，进入“系统设置 → 隐私与安全性 → 辅助功能”。部分较新系统显示为“设备控制和数据访问”。添加并开启 **QQ 聊天 Bot（开源版）**。若列表中只显示可执行文件名，请选择此项目内的 `QQChatBridge.app`。
6. 点击“保存并重启后台”，然后从菜单栏点击“开始监听”。查看“诊断”和实时状态确认 QQ、权限、后台和当前模型正常。

默认只监听指定主群；其他群和私聊、网页浏览、自动主动话题、生图、空间定时互动及桌宠均默认关闭。按自己的需求在设置中启用。启用全会话回复后，仍由模型决定是否接话。

### 权限说明

辅助功能权限用于读取 QQ 消息和操作输入框、菜单、切换会话。它是必需的；这不是直接连接 QQ 服务器的协议机器人。

重新编译或更换签名后，macOS 可能撤销原来的辅助功能授权：到同一权限页关闭再开启即可。使用开源包不需要授予私人版应用权限。

放在“文稿”“下载”等受保护位置时，系统可能询问文件夹访问；应用需要读取自身目录并写入 `config.json`、`runtime/`。如果仍无法访问，可使用目录授权入口：

```sh
open -n ./QQChatBridge.app --args --authorize-project
```

在弹出的文件夹选择器里选择解压后的项目目录。正常运行不要求屏幕录制或完全磁盘访问；系统通知为可选权限。保持电脑唤醒、联网，QQ 和应用持续运行。QQ 操作会切换当前桌面窗口并使用剪贴板，近期键盘输入或已有草稿时会等待。

## 从源码编译

```sh
xcode-select --install
zsh build.sh
open QQChatBridge.app
```

已安装开发工具时不必重复安装。脚本按本机架构编译并签名。设置中的 Python 路径留空时按项目 `.venv`、Homebrew、`/usr/local/bin` 和系统 Python 顺序查找；也可以填写 Python 的完整路径。建议显式使用你安装的 Python 3.10+。

## 可选网页和视频功能

基础聊天不需要浏览器依赖。启用完整网页浏览、播放或视频画面分析时，在项目目录建立环境：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-browser.txt
.venv/bin/python -m playwright install chromium
```

设置中将 Python 路径留空（会先查找 `.venv`），或填 `.venv/bin/python3` 的**完整路径**，再开启“浏览器任务”并保存重启。浏览器使用独立环境，不自动复用你的个人浏览器登录态；遇到需登录的页面可能读不到。没有 Chromium 时，部分网页只尝试通过 Jina Reader 读取文字。

视频优先读取字幕，只有无可用字幕或确实需要画面时才抽帧；稀疏帧不能代替完整视频和音频。网页阅读或检索可能访问 Jina Reader、Google News、YouTube 等外部服务。分析仍使用你在 AI 供应商页填写的模型；不同站点是否可读取取决于页面结构、登录要求和网络。

## 图片生成

到“图片 → 图片生成”填写完整接口地址、模型名称、API Key、尺寸和每人 24 小时上限，然后启用：

- OpenAI 兼容接口：完整地址以 `/images/generations` 结尾，支持 `data[].b64_json` 或 `data[].url` 返回值。
- 也支持 `multimodal-generation` 类型的 `input.messages` 生图接口；具体尺寸须由服务支持。

生图审核使用同一个聊天 AI，实际图片由独立生图接口生成。未填完整配置时不要开启。配额按最近 24 小时的生成记录计算，不是在午夜统一清零；公开配置没有特权用户名。生图、审核、失败重试和视频画面都可能消耗供应商额度。

## 主动话题与 QQ 空间

“AI 供应商 → 启用自动主动话题”可在群聊沉默后概率开场；菜单栏提供手动触发按钮，部分话题先供你选择。检索和内容分析使用相同 AI；主动话题不做广告引流。

QQ 空间复用 QQ 内置浏览器登录态。填写自己的 QQ 号后，从菜单栏打开“QQ 空间”，手动开始一轮或启用定时浏览。定时按你在设置中选择的时区与时间运行。默认没有启用自动点赞、评论或定时任务。新账号需要先实际检查空间页面能被读取。

## 数据存放与隐私

公开仓库和发布包只有源码、通用提示词、空白配置模板、程序资源和许可文件，**不含作者的 API Key、QQ 号、群名、群聊记录、长期总结、群友资料、角色提示词、表情库或旧测试数据**。

运行后产生的数据在自己电脑中：

| 文件 | 内容 |
| --- | --- |
| `config.json` | 本机账号、主群、接口与密钥等设置 |
| `runtime/messages.jsonl` | 按聊天区分的消息记录 |
| `runtime/style-profile.json` | 自动学习的风格摘要和会话记忆 |
| `runtime/people.json` 等运行文件 | 自己添加的群友备注、反馈与统计 |
| `runtime/status.json`、`runtime/live.json` | 当前状态、实时处理说明 |
| `runtime/bridge.log`、`runtime/backend.log` | 运行日志与错误 |

这些目录已被 Git 忽略。AI 处理时，相应消息、上下文、摘要以及选中的图片会发送到**你配置的 AI 服务**；空间或网页处理时相关可读内容也会发送到该服务。仓库没有上传运行数据的功能。不要把使用后的整个文件夹重新公开上传；分享修改时上传源码即可。

## 常见问题

- **不回复**：查看实时窗口和日志，是模型决定不接话、接口失败还是发送未确认；检查昵称、主群名称、辅助功能权限和当前草稿。
- **接口报错**：核对 URL 是否为 Chat Completions 兼容端点、模型名称、密钥和模型的图片能力。供应商拒绝 `response_format`、`temperature` 或 `reasoning_effort` 时会尝试省略对应可选字段。
- **图片没读到**：QQ 的图片加载、复制菜单和窗口可见性会影响读取。读取失败时跳过或说明实际情况，不凭内容猜测。
- **消息停在输入框**：程序会暂停避免重复发送，先人工检查输入框，再恢复监听。
- **运行受键盘输入打断**：程序会等待你停止打字，以减少将按键送错到 QQ 的机会。
- **QQ 更新后失效**：本项目依赖 QQ 的辅助功能界面结构，界面更新可能需要适配。
- **为什么不是后台无窗口机器人**：消息读取与发送依赖已登录的 QQ 桌面客户端，因此需要真实窗口与系统权限。

开源版已做源码和构建检查；不同 QQ 版本、Intel Mac、不同 AI 服务和网页的兼容性仍需在对应环境确认。

## 目录与贡献

`Sources/` 是原生应用；`bridge.py` 为后台入口；`engine*.py` 负责调度和发送；`ai_client.py`、`llm.py` 统一 AI 接口；`prompts/` 为通用规则；`config.example.json` 是公开模板。`AGENT.md` 说明当前架构和已知限制。

GitHub 通常上传**源码、README、配置模板和许可证**；现成应用放在 **Releases**。本项目也提供源码 ZIP，下载者无需了解 Git 即可开始。
